# 기능 상세 설계

본 문서는 5개 핵심 기능의 설계를 기술한다. 개요는 [overview.md](overview.md) 참고.

---

## 기능 1 — RAG 기반 점검 + 버전 관리 (관리 시스템 지정·해제)

### 구성 요소

- **점검 지식베이스 (RAG)**: KISA 주요정보통신기반시설 취약점 분석·평가 기준(U-series),
  CIS Benchmarks, DISA STIG, CVE/NVD를 임베딩하여 벡터 DB에 저장. 대상 시스템 프로파일로
  관련 점검 항목과 **근거 문서**를 검색.
- **자산 인벤토리 (CMDB)**: 관계형 DB. 시스템 등록/해제(관리 대상 지정·해제),
  에이전트 설치 상태, 마지막 점검 시각, OS/버전 메타데이터 추적.
- **버전 관리 (이중화)**:
  1. 점검 기준(체크리스트) 버전 — 기준 개정 이력 추적
  2. 시스템 설정 스냅샷 버전 — Git 저장소에 보관하여 diff·롤백

### 설계 결정

- RAG는 "무엇을 왜 점검하는가 + 근거" 제공용. **합격/불합격 판정은 결정론적 룰 엔진**이 담당.
- 자산 관리는 RAG가 아닌 **관계형 CMDB**로 구현.

### 데이터 모델 (개략)

```
asset(id, hostname, os, os_version, role, managed_bool, agent_status, last_scan_at)
checklist_version(id, standard, version, effective_date)
config_snapshot(asset_id, git_ref, captured_at)   # 본문은 Git에 저장
```

## 기능 2 — 프로세스 탐색 + 연관 파일 자동 관리

### 수집 전략

| 설치 방식 | 식별 방법 | 연관 파일 매핑 |
|-----------|-----------|----------------|
| 패키지 | `rpm -qa` / `dpkg -l` / `pacman -Q` | `rpm -ql` / `dpkg -L` (결정론적) |
| 소스 설치 | `/usr/local`·`/opt` 스캔, `/proc/<pid>/exe`, `lsof` | 열린 FD, 환경변수, systemd unit `ExecStart`/`WorkingDirectory` |

### LLM 보조 역할

소스 설치는 결정론적 매핑이 어렵다. LLM이 "바이너리 경로 + 오픈 파일 패턴"을 보고
어떤 서비스(nginx, tomcat 등)인지, 설정/로그 파일이 어디일 가능성이 높은지 추론한다.
추론 결과는 **후보(candidate)** 로 표시하고 결정론적 검증을 덧붙인다.

### 보안 주의

수집한 파일명·경로·로그는 LLM 컨텍스트에 들어가면 **프롬프트 인젝션 벡터**가 된다.
수집 데이터는 항상 "데이터"로만 취급하고 시스템 프롬프트와 분리한다 ([위협 모델](threat-model.md) 참고).

## 기능 3 — 무결성 유지 + 부정행위 탐지

### 무결성 (FIM)

- 베이스라인 해시(SHA-256) 저장 → 주기 비교.
- AIDE/Tripwire 래핑 또는 자체 구현. 베이스라인은 서명하여 변조 방지.

### 부정행위 탐지

바이너리/설정 무단 변경, 점검 회피(로그 삭제, 타임스탬프 조작), **에이전트 자체 변조**를 감지.

- **실시간·대량 이벤트**: 규칙 + 통계 모델 (LLM은 비용·지연으로 부적합).
- **맥락 판단**: 변경 이벤트 묶음이 정상 운영(패치)인지 공격 징후인지 LLM이 보조 판단.

### 에이전트 self-protection (필수)

점검 에이전트 자신의 무결성과 결과 전송 구간을 보호하지 않으면 **점검 결과 위조**가 가능하다.
- 에이전트 바이너리 서명 검증
- 결과 전송 서명(Ed25519) + mTLS

## 기능 4 — 시스템에 맞는 점검 도구 자동 선택

### 라우팅 매핑

| 대상 유형 | 도구 |
|-----------|------|
| OS 설정 | OpenSCAP, Lynis |
| 네트워크 | Nmap |
| 컨테이너/이미지 | Trivy, Grype |
| 웹 | OWASP ZAP, Nikto |
| 패키지 CVE | OSV-Scanner, Trivy |

### 구현

LLM이 대상 프로파일(OS, 역할, 노출 범위, 설치 소프트웨어)을 입력받아
**도구 레지스트리 내에서 function calling/tool use로 선택**한다.
- 도구 레지스트리 = 허용된 도구 + 파라미터 JSON 스키마.
- Allowlist 밖 명령은 실행 불가.

## 기능 5 — 조치 방안 생성 + 샌드박스 검증

가장 가치가 크면서 가장 위험한 기능. 아래 파이프라인을 **반드시** 거친다.

```
LLM 조치안 생성
  → 정적 분석 (파괴적 명령 차단: rm -rf, dd, userdel 등)
  → 롤백 스크립트 동시 생성
  → 샌드박스 적용 (설정 스냅샷 복원 후)
  → 점검 재실행 (통과로 바뀌는가 + 서비스 정상인가 = 멱등성·부작용 확인)
  → 검증 리포트 + diff 미리보기
  → [HITL] 사람 승인
  → 운영 반영 (또는 거부)
```

### 샌드박스 환경

- OS 설정 조치: 대상과 동일 이미지의 **컨테이너**.
- 커널/전체 시스템 조치: **일회성 VM** (Firecracker/QEMU).
- 현재 설정 스냅샷을 복원하여 "운영과 동일 상태"에서 검증.

### 리스크 완화

- 생성 스크립트 정적 분석 (파괴적/비가역 명령 거부)
- 롤백 스크립트 필수 동반
- diff 미리보기 및 사람 승인 게이트
