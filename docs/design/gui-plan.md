# GUI 구현 계획

LeJuSec 운영자용 웹 콘솔(Operator Console)의 구현 계획. 컨트롤 플레인 REST API
([../../control-plane/README.md](../../control-plane/README.md)) 위에 올라가는 프런트엔드로,
자산 관리·점검 결과·**조치 승인(HITL)**·무결성 이벤트·근거(RAG) 조회를 제공한다.

## 1. 목적과 범위

- **대상 사용자**: 보안 점검 담당자/운영자 (에이전트가 아님).
- **핵심 가치**: 분산된 점검·조치 결과를 한 화면에서 보고, **조치 승인 게이트(HITL)**를 안전하게 운영.
- **범위 밖(초기)**: 에이전트가 쓰는 서명/mTLS 경로는 GUI와 무관하게 유지. GUI는 운영자 인증으로 보호되는 별도 평면.

## 2. 아키텍처

```
[운영자 브라우저] ──HTTPS──> [GUI (SPA, 정적 번들)]
                                   │ REST (쿠키/토큰 세션)
                                   ▼
                        [Control Plane FastAPI]  ── 기존 API 재사용
```

- **SPA(단일 페이지 앱)** 로 구현: 점검/조치 검토는 상호작용이 많아 서버 렌더링보다 적합.
- 배포: 정적 번들을 ① 컨트롤 플레인이 서빙(`/ui`)하거나 ② 별도 정적 호스팅. 초기엔 ①로 단순화.
- 저장소 위치: 신규 `web/` 디렉터리(모노레포 유지).

## 3. 기술 스택 (권장)

| 영역 | 선택 | 비고 |
|------|------|------|
| 언어/프레임워크 | **React 18 + TypeScript** | 생태계·타입 안전 |
| 번들러 | **Vite** | 빠른 개발 서버, 정적 빌드 |
| 데이터 패칭 | **TanStack Query** | 캐시·동기화·로딩/에러 처리 |
| 라우팅 | **React Router** | |
| UI 컴포넌트 | **Mantine** 또는 shadcn/ui | 테이블·폼·모달·코드블록 |
| 차트 | **Recharts** | 점검 통과/실패 요약 |
| 테스트 | **Vitest + Testing Library**, **Playwright**(E2E) | |
| 린트/포맷 | **ESLint + Prettier** | CI에 추가 |

> 백엔드가 Go/Python인 것과 별개로, 프런트는 React/TS가 가장 합리적. 팀 역량에 따라
> Svelte/Vue도 가능하나 본 계획은 React 기준.

## 4. 화면(페이지) 구성

1. **대시보드** — 자산 수, 관리/미관리, 최근 점검 요약(통과/실패/비적용), 미승인 조치 수, 최근 무결성 이벤트(심각도별).
2. **자산 목록** — 등록/검색/필터, 관리 지정·해제, 삭제, 에이전트 상태.
3. **자산 상세** — 탭 구성:
   - *인벤토리*: 패키지/프로세스 스냅샷
   - *점검 결과*: 체크별 pass/fail/na + 사유 + 근거(RAG) 링크
   - *조치*: 조치안 목록과 상태
   - *무결성*: 베이스라인 요약 + 변경 이벤트(심각도)
4. **조치 검토(HITL)** — 핵심 화면:
   - 조치/롤백 스크립트 **미리보기(diff/코드블록)**
   - **정적 분석 상태**(통과/위반 사유), **샌드박스 검증 결과**
   - **승인/거부** 버튼 — *정적 분석 위반 조치는 승인 버튼 비활성화*
5. **점검 기준 브라우저** — 전체 기준 목록 + **RAG 근거 검색**(`/checks/search`).

## 5. API 매핑과 백엔드 보강 필요

| 화면 | 사용 API (기존) | 보강 필요 |
|------|-----------------|-----------|
| 대시보드 | 여러 목록 집계 | **요약(aggregation) 엔드포인트** 추가 권장 |
| 자산 | `/assets*` | 목록 **페이지네이션/필터** |
| 점검 결과 | `/assets/{id}/results` | - |
| 조치 검토 | `/assets/{id}/remediations`, `/remediations/{id}/verify|approve|reject` | - |
| 무결성 | `/assets/{id}/integrity/events|baseline` | 이벤트 **페이지네이션**, (선택) 실시간 알림(SSE) |
| 기준/근거 | `/checks`, `/checks/search` | - |

**공통 백엔드 보강**
- **운영자 인증/인가(RBAC)**: 세션 또는 OAuth/OIDC. 승인 권한 분리(검토자 vs 승인자).
- **CORS** 설정(별도 호스팅 시) 또는 동일 출처 서빙.
- 감사 로그: 누가 언제 승인/거부했는지 기록.

## 6. 보안 고려사항

- GUI는 **운영자 인증 뒤에만** 노출, HTTPS 필수.
- 에이전트 개인키·서명 키는 GUI에 **절대 노출 금지**(GUI는 조회/승인만).
- 승인은 서버에서 재검증(정적 분석 위반 조치 승인 차단 로직은 API에 이미 존재 → GUI는 보조 UX).
- CSRF 방지(토큰/SameSite 쿠키), XSS 방지(React 기본 이스케이프 + 스크립트 미리보기는 코드블록으로만 렌더, 실행 금지).
- 조치 스크립트 미리보기는 **표시 전용** — 브라우저에서 실행하지 않는다.

## 7. 단계별 로드맵

- **G1 — 읽기 전용 콘솔** *(구현됨: `web/`)*: 대시보드 + 자산 목록/상세(개요·인벤토리·점검 결과·무결성·조치 조회). 집계 엔드포인트(`/summary`)·인벤토리 조회·CORS 추가.
- **G2 — HITL 조치 검토** *(구현됨)*: 조치안 생성, 스크립트/롤백 미리보기 + 정적 분석/샌드박스 상태 표시 + 샌드박스 검증·승인·거부(정적 분석 위반은 승인 버튼 비활성화).
- **G3 — 근거/탐지 강화** *(구현됨)*: 점검 기준 목록 + `/checks/search` 근거 검색 UI, 무결성 변경 **실시간 알림(SSE, `/events/integrity`)** 으로 자산 상세가 자동 갱신.
- **G4 — 인증·감사·폴리시** *(인증/RBAC·감사 로깅 구현됨)*: 운영자 베어러 토큰 + 역할(admin/viewer) 미들웨어(에이전트 서명 엔드포인트 면제), 쓰기 성공 **DB 감사 로그**(`GET /audit`, GUI 감사 페이지), GUI 토큰 입력·역할별 쓰기 버튼 게이팅. (다크모드·i18n은 추후.)

## 8. CI/빌드

- `web/`에 ESLint·Prettier·Vitest 구성, `ci.yml`에 `web` job 추가(설치·린트·테스트·빌드).
- 정적 번들을 컨트롤 플레인 `/ui`로 서빙하는 경우, 릴리스에 번들 포함.
