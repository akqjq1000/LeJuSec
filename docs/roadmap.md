# 개발 로드맵

전략: **결정론적 뼈대를 먼저, AI를 그 위에.** 각 단계는 독립적으로 가치를 제공한다.

## MVP 순서

### Phase 1 — 자산 + 수집 (기능 1·2)
- [x] 컨트롤 플레인 골격 (FastAPI)
- [x] 자산 CMDB: 시스템 등록/지정(manage)/해제(unmanage)/삭제
- [x] Go 에이전트: 패키지(dpkg/rpm/pacman)·프로세스(/proc) 수집
- [x] 연관 파일(설정·로그) 매핑 (패키지 기반, `PackageFiles`)
- [x] Ed25519 서명 전송: 에이전트 서명 → 컨트롤 플레인 검증 후 인벤토리 수신
- [x] mTLS 전송 구간 보호: 자가 CA 발급(server/client), uvicorn 상호 TLS, 에이전트 클라이언트 인증서

**완료 기준**: 대상 시스템을 등록하고, 설치된 패키지·프로세스·연관 파일 목록을 서명된 결과로 수집한다. → **충족** (Ubuntu 26.04 실서버 연동 검증 완료, 전송 구간 mTLS 적용).

### Phase 2 — 점검 + RAG 근거 (기능 1·4)
- [ ] 점검 도구 래핑 (OpenSCAP, Lynis, Trivy)
- [ ] 룰 엔진: 결정론적 합격/불합격 판정
- [ ] RAG 지식베이스: 점검 기준(KISA/CIS) 임베딩, 근거 검색
- [ ] Orchestrator: 프로파일 기반 도구 라우팅 (allowlist)
- [ ] 점검 결과 + 근거 저장, 증적 서명

**완료 기준**: 대상에 맞는 도구가 자동 선택되어 점검이 실행되고, 판정 결과에 근거가 첨부된다.

### Phase 3 — 조치 + 샌드박스 (기능 5)
- [ ] 조치안 + 롤백 스크립트 LLM 생성
- [ ] 정적 분석 (파괴적 명령 차단)
- [ ] Sandbox Runner: 스냅샷 복원 → 적용 → 재점검
- [ ] HITL 승인 워크플로우
- [ ] diff 미리보기 + 검증 리포트

**완료 기준**: 불합격 항목에 대해 조치안이 생성·격리 검증되고, 사람 승인 후에만 반영된다.

### Phase 4 — 무결성 + 탐지 (기능 3)
- [ ] FIM: 베이스라인 해시, 주기 비교
- [ ] 부정행위 탐지 규칙 + 통계 모델
- [ ] 변경 이벤트 맥락 판단 (LLM 보조)
- [ ] 에이전트 self-protection 강화

**완료 기준**: 설정·바이너리 변조와 점검 회피 징후를 탐지하고 맥락을 분류한다.

## 횡단 과제 (전 단계 공통)
