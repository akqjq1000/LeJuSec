# 개발 로드맵

전략: **결정론적 뼈대를 먼저, AI를 그 위에.** 각 단계는 독립적으로 가치를 제공한다.

## MVP 순서

### Phase 1 — 자산 + 수집 (기능 1·2)
- [x] 컨트롤 플레인 골격 (FastAPI)
- [x] 자산 CMDB: 시스템 등록/지정(manage)/해제(unmanage)/삭제
- [x] Go 에이전트: 패키지(dpkg/rpm/pacman)·프로세스(/proc) 수집
- [x] 연관 파일(설정·로그) 매핑 (패키지 기반, `PackageFiles`)
- [x] Ed25519 서명 전송: 에이전트 서명 → 컨트롤 플레인 검증 후 인벤토리 수신
- [x] mTLS 전송 구간 보호: 자가 CA 발급(server/client), uvicorn 상호 TLS, 에이전트 클라이언트 인증서

**완료 기준**: 대상 시스템을 등록하고, 설치된 패키지·프로세스·연관 파일 목록을 서명된 결과로 수집한다. → **충족** (Ubuntu 26.04 실서버 연동 검증 완료, 전송 구간 mTLS 적용).

### Phase 2 — 점검 + RAG 근거 (기능 1·4)
- [x] 점검 도구 래핑 (OpenSCAP/Lynis/Trivy 결과 파서 → 정규화 Finding)
- [x] 룰 엔진: 결정론적 합격/불합격/비적용 판정 (`rules.evaluate`)
- [x] RAG 지식베이스: 점검 기준(KISA/CIS) 코퍼스 + 근거 검색 (해싱 임베딩 코사인 기본, 어휘 백엔드 선택 가능, 공급자 교체 가능)
- [x] 도구 라우팅: 대상 유형별 allowlist (`scanners.select_tools`)
- [x] 점검 결과 저장 + 서명 수신 (`POST /assets/{id}/scan`, 증적 원본 보관)

- [x] 에이전트 스캐너 실행: Trivy/Lynis/OpenSCAP 실행·파싱 → 서명 전송(`POST /assets/{id}/scan`, `--scan`)
- [x] 임베딩 기반 RAG: 해싱 임베딩 코사인 검색(`LEJUSEC_RAG_BACKEND`), `EmbeddingProvider` 교체 가능

**완료 기준**: 대상에 맞는 도구가 자동 선택되어 점검이 실행되고, 판정 결과에 근거가 첨부된다. → **충족**.

### Phase 3 — 조치 + 샌드박스 (기능 5)
- [x] 조치안 + 롤백 생성: 지식베이스 템플릿(기본) + Claude LLM 생성기(선택, `LEJUSEC_GENERATOR_BACKEND=llm`) — 실패/위험 시 템플릿 폴백, LLM 출력도 정적분석 게이트 통과 필수
- [x] 정적 분석: 파괴적/비가역 명령 차단(denylist), 위반 시 승인 불가
- [x] 샌드박스 검증: 드라이런(정적 재확인 + 롤백 존재) — 컨테이너/VM 러너로 교체 가능
- [x] HITL 승인 워크플로우: proposed → verify → approve/reject (unsafe는 승인 불가)
- [x] 미리보기 + 리포트: 조치/롤백 스크립트 노출 + 검증 결과

**완료 기준**: 불합격 항목에 대해 조치안이 생성·검증되고, 사람 승인 후에만 반영된다. → 생성·정적분석·검증·승인 게이트 완료. (남음: 실제 컨테이너 샌드박스 실행, LLM 생성기, 승인→에이전트 적용 연동)

### Phase 4 — 무결성 + 탐지 (기능 3)
- [x] FIM: 에이전트 SHA-256 매니페스트 + 중앙 베이스라인 비교(추가/수정/삭제)
- [x] 부정행위 탐지 규칙: 핵심 경로/삭제 기반 심각도 분류 (통계 모델은 추후)
- [ ] 변경 이벤트 맥락 판단 (LLM 보조) — 교체 가능한 자리
- [x] 에이전트 self-protection: 자체 바이너리 해시 중앙 검증(변조=critical) + 서명 리포트

**완료 기준**: 설정·바이너리 변조와 점검 회피 징후를 탐지하고 맥락을 분류한다. → 변조 탐지·분류 완료. (남음: 통계 이상 탐지, LLM 맥락 판단)
